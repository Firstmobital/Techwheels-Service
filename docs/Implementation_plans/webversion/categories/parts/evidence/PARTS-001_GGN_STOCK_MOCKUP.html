✅ Order Date Validation Logic

Prevents an old order from being matched with a current vehicle/part requirement. When the relevant order/request reference date is X, the Order Date must not be earlier than X.

Required Date (X) Order Date Result Explanation
24-Aug-2026 23-Aug-2026 ❌ Ignore Order date is before requirement date — old order for another vehicle
24-Aug-2026 24-Aug-2026 ✅ Valid Same date — order placed on the same day as requirement
24-Aug-2026 25-Aug-2026 ✅ Valid Future date — order placed after requirement was raised
24-Aug-2026 — No Match No order found for this part number in the Order Sheet
Matching Priority
  1. Match the relevant Part Number from the Order Sheet
  2. Apply the applicable vehicle/request reference (Entry Date = X)
  3. Check the Order Date against X
  4. Ignore all records where Order Date < X
  5. From remaining valid records, use the latest valid order to update Order No., Order Date, and Order Status
Current State & Enhancement:
• The parts-request-order-match edge function ALREADY has partial validation (rejects Order Date before Entry Date)
• Enhancement: strengthen the matching logic to explicitly filter out all Order Sheet rows with Order Date < Entry Date before selecting the best match, rather than just checking the final candidate
• This prevents edge cases where an old order with a newer updated_at timestamp could slip through

Matching & Normalization Logic:
1. Primary match: Part Number (Column A) — normalized (trim, uppercase, remove spaces)
2. Normalization: Remove leading/trailing spaces · Ignore case differences · Handle numeric/text formatting
3. Duplicate handling: If duplicate Part Numbers exist, sum the Free Stock values or use the latest row
4. Stock determination: Column P (Free Stock) > 0 → "Available" · ≤ 0 → "Not Available" · No match → "No Data"
5. Auto-refresh: Status updates when Part Number changes, vehicle/job details change, or new sheet is uploaded
